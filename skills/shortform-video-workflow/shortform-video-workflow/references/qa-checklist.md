# Short-form Video QA Checklist

Run this checklist before calling a brief production-ready.

## Proposition and hook
- [ ] The video communicates one primary proposition.
- [ ] The viewer can understand why the video matters within the opening beat.
- [ ] The hook is specific enough to visualize.
- [ ] The body actually resolves the hook.
- [ ] The hook does not depend on unsupported exaggeration.

## Claims and evidence
- [ ] Quantitative claims are verified or explicitly user-provided.
- [ ] Testimonials/results are traceable to supplied or retrieved evidence.
- [ ] Current or externally verifiable claims have a source when tools permit.
- [ ] Inferences are not worded as established facts.

## Script
- [ ] Background exposition is minimal.
- [ ] Concrete mechanism/example appears before abstract slogan language.
- [ ] Every beat has a clear narrative function.
- [ ] No sentence exists only because the source contained it.
- [ ] CTA asks for one main action.

## Text layers
- [ ] Voice, subtitle, and hero text have different jobs.
- [ ] Hero text is concise, normally <=8 words.
- [ ] Subtitle chunks are normally <=2 lines.
- [ ] Important terms are emphasized selectively, not everywhere.

## Visuals
- [ ] First-party UI/footage and evidence were considered before generic stock.
- [ ] Visuals semantically match the narration.
- [ ] No more than two consecutive beats use identical visual grammar without a reason.
- [ ] Motion graphics are used when they explain, not merely decorate.
- [ ] Generic B-roll is used mainly for context/emotion/reset, not as fake proof.

## Pacing
- [ ] There is a meaningful perceptual event roughly every 2-4 seconds by default.
- [ ] Complex ideas are allowed enough time to be understood.
- [ ] Motion is not random or hyperactive.
- [ ] Outro/CTA is concise.

## Brand and originality
- [ ] Brand system is consistent across typography, color, motion, and UI treatment.
- [ ] Reference creators inform mechanisms, not exact imitation.
- [ ] The final video still has a distinctive brand identity.

## Production readiness
- [ ] Every beat names an asset or a clear asset need.
- [ ] Missing assets are explicitly flagged.
- [ ] Rights/provenance concerns are flagged when applicable.
- [ ] The plan can be handed to an editor without reconstructing the creative logic.
